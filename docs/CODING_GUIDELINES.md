# Coding Guidelines

- TypeScript preferred for all files.
- Use `camelCase` for variables and functions.
- Use `PascalCase` for React components and classes.
- Ensure meaningful variable and function names.
- Create modular reusable components.
- No unnecessary duplication or boilerplate.
- Use environment variables for secrets; commit NO secrets.
- Backend validation required for all payload data.
- Frontend validation required for rapid user feedback.
- Return consistent API response structures (`{ success, data, message }`).
- Do not add unnecessary project dependencies.
